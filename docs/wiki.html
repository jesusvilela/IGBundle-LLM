IGBundle: evidence and limitations

An information-geometric, fiber-structured adapter is a research hypothesis, not a demonstrated performance improvement.

Current conclusion
The fixed geometric operators pass the recorded local audit. Current experiments do not establish that a trained IGBundle model learns hyperbolic semantic structure or outperforms a suitable baseline. A small paired token-NLL probe favored its vanilla-LoRA control, but parameter count and layer coverage were confounded.

1. Research design

IGBundle explores Poincare-ball coordinates, categorical fiber components, and geometric or dynamical operators as a possible inductive bias for adapting language models. The bundle terminology describes the intended parameterization; it is not evidence that model representations form a learned fiber bundle.

The default curvature readout is generated by a fixed conformal factor and is weight-invariant. It must not be interpreted as learned curvature. The default curvature regularizer therefore does not establish that training moved the model toward a target curvature. See the repository's falsification analysis for the derivation and scope.

3. October 2026 local subset evaluation

A local run on 27 October compared the base Qwen2.5-7B model, an exported cp300 checkpoint, and a reconstructed composite with runtime IGBundle adapters. It used fixed, small subsets (8–98 examples per benchmark), greedy decoding, and a custom weighted index.

Variant Custom weighted index Evaluation artifact

Merged cp300 checkpoint60.0Q4_K_M GGUF
Reconstructed adapter composite64.7Runtime adapters grafted onto cp300; NF4/bf16 loading path

The index is an exploratory custom weighted average (weights: MMLU-Pro .30, ARC-Challenge .10, MATH-500 .25, GSM8K .10, IFBench-lite .15, degeneration probes .10), not a standardized benchmark or a significance test. No individual paired benchmark difference was statistically significant; corrected-vs-cp300 McNemar p-values were at least 0.63.

The exported cp300 weights did not contain the runtime geometric adapter. The reconstructed arm attached a surviving adapter trained on the base model to cp300; it is not the original trained checkpoint. Its quantization/loading path also differed from the GGUF arms. This post-hoc reconstruction does not isolate a geometric effect or confirm a benefit. See the per-benchmark summary.

4. September 2026 paired language-modeling probe

On 20 September 2026, one geometric checkpoint (A) and one vanilla-LoRA control (B) were scored against the same base snapshot on 24 held-out examples, with 64 tokens scored per example. The shared run conditions included the base, corpus, seed, 500 training steps, learning rate, and sequence length.

Arm Mean token NLL
Bare frozen base2.3188
Geometric adapter A1.9352
Vanilla-LoRA control B0.8187

B had lower NLL on all 24 paired examples. The mean paired difference A - B was +1.1165 (95% paired t interval [0.9144, 1.3186]; t = 11.4275; two-sided p = 5.83 × 10⁻¹¹). The paired measurements are provided without prompt text.

This is a small next-token likelihood probe, not task accuracy. The arms are not parameter matched: A has 4,160,713 trainable parameters and B has 585,728. A uses one geometric layer; B uses 13 LoRA layers. The result does not isolate geometry from adapter family, layer coverage, or objective, and should not be generalized beyond these tested arms.

6. What would test the hypothesis?

A causal geometry comparison needs matched trainable-parameter budgets and layer placement, a shared data split and training budget, multiple seeds, task-level evaluation, and an ablation that changes only the geometric operator or objective. Publish the exact checkpoint/configuration and raw outputs with each result. Until then, the method remains an open research hypothesis.
